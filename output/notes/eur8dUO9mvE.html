Introduction to Model Context Protocol (MCP)

An architectural breakdown of the Model Context Protocol (MCP), an open-source standard designed to connect AI agents to external data sources such as databases, APIs, and local code environments.

Model Context Protocol (MCP)

What it is
An open-source communication standard and transport layer protocol that standardizes how AI applications and agents connect to external tools and data sources.
How it works
Acts as an intermediary transport layer between an MCP client application and one or more MCP servers, standardizing tool discovery, request execution, and response routing.
Key points
  • Eliminates custom, ad-hoc integrations for every external database or API.
  • Separates client-side orchestration from tool execution logic.
  • Allows a single host or client to connect to multiple MCP servers simultaneously.
When to use
When developing AI agents or LLM-powered applications that need reliable, standardized access to external systems like SQL/NoSQL databases, REST/GraphQL APIs, or local files.

MCP Host and Client

What it is
The user-facing runtime application (the host) and its internal connection interface (the client) that manage agent interaction and coordinate with LLMs.
How it works
The host (such as a chat application or IDE code assistant) contains one or more MCP clients. It discovers available tools from registered MCP servers, formats prompt context for the LLM, and dispatches tool execution requests.
Key points
  • A single MCP host can manage one or multiple MCP clients.
  • Common host implementations include chat interfaces, IDE extensions, and automated workflows.
  • The host mediates between the user, the LLM, and the downstream MCP servers.
When to use
When building or configuring the primary environment where user interactions occur and where agentic decisions are routed to LLMs.

MCP Server

What it is
A lightweight service that exposes specific capabilities, data sources, or executable functions as standardized MCP tools.
How it works
Registers available tools with the MCP host on demand, listens for tool-use execution requests across the MCP protocol, interfaces directly with external resources (databases, APIs, or local code), and returns structured outputs.
Key points
  • Agnostic to backend implementations (works with relational DBs, NoSQL, APIs, or file systems).
  • Hosts can connect to arbitrary numbers of independent MCP servers.
  • Encapsulates authentication, schema mapping, and query logic away from the LLM prompt.
When to use
When wrapping an internal database, SaaS API, or local execution environment to expose its functionality safely to LLM agents.

MCP Agent Execution Workflow

What it is
The multi-step interaction loop through which an MCP host discovers tools, consults an LLM, invokes tools via MCP servers, and generates a grounded response.
How it works
The host receives a user question, queries MCP servers for available tools, and forwards both the question and tool definitions to the LLM. When the LLM requests a tool call, the host routes it to the designated MCP server, executes against the data source, feeds the result back to the LLM, and receives the final answer.
Key points
  • Tool discovery happens dynamically prior to or during the prompt assembly.
  • Execution is iterative: tool results can prompt subsequent tool calls or final answer generation.
  • The LLM decides which tool to call, but the MCP server executes the operation and retrieves real data.
When to use
When architecting agentic request-response lifecycles that require external data grounding and tool execution.
