Machine Learning Development Life Cycle (MLDLC)

This lecture outlines the end-to-end Machine Learning Development Life Cycle (MLDLC/MLDC), presenting a standard 9-step roadmap for taking machine learning ideas from initial problem framing to deployment and production optimization.

Machine Learning Development Life Cycle (MLDLC)

What it is
A standardized set of guidelines and procedural phases used across the industry to build, deploy, and maintain end-to-end ML-based software products.
How it works
Modeled after the Software Development Life Cycle (SDLC), MLDLC structures ML projects into distinct iterative stages covering problem formulation, data processing, modeling, deployment, and post-launch maintenance.
Key points
  • Iterative framework bridging research/experimentation and production software.
  • Prevents common beginner mistake of only training models and stopping after measuring accuracy.
  • Required standard for developing production-grade, end-to-end ML applications.
When to use
Use as a foundational development blueprint for any enterprise or production-level machine learning project.

Stage 1: Frame the Problem

What it is
The requirement-gathering and scoping phase where business goals and technical problem architectures are defined.
How it works
The team clarifies client goals, target audience, budget, team size, and defines whether the problem is supervised/unsupervised, online/batch, and which class of ML algorithms to consider.
Key points
  • Defines end-product vision, KPIs, and operational constraints early to avoid costly mid-project redesigns.
  • Determines data requirements and system execution modes (offline batch vs. real-time online inference).
  • Establishes initial feasibility and business value.
When to use
Use at the very beginning of a project before writing any code or gathering data.

Stage 2: Gathering Data

What it is
The process of collecting relevant raw data required to train machine learning models from internal or external sources.
How it works
Data is sourced via direct CSV files, hitting APIs returning JSON, web scraping unstructured web pages, extracting from operational databases/data warehouses via ETL pipelines, or querying distributed cluster tools like Apache Spark for big data.
Key points
  • Real-world data is rarely readily available in single clean files compared to academic/competition datasets.
  • Utilizes techniques like ETL (Extract, Transform, Load) to feed data from production databases into warehouses.
  • Must store gathered data in formats readily accessible for pre-processing.
When to use
Use right after problem framing to assemble the training and validation datasets.

Stage 3: Data Preprocessing

What it is
Cleaning raw data and preparing its structure to make it suitable and safe for machine learning algorithms.
How it works
Transforms noisy or dirty data by removing duplicates, handling missing values, removing outliers, and applying feature scaling (such as standardization or normalization) to bring features to comparable scales.
Key points
  • Prevents garbage-in, garbage-out failure modes in mathematical optimization algorithms.
  • Handles data compatibility and structural inconsistencies across multiple sources.
  • Scaling prevents distance-based algorithms from being biased toward large-magnitude numbers.
When to use
Use immediately after raw data acquisition to sanitize inputs prior to analysis and model consumption.

Stage 4: Exploratory Data Analysis (EDA)

What it is
The analytical process of investigating dataset characteristics, distributions, patterns, and anomalies using visualization and statistical methods.
How it works
Applies univariate analysis (analyzing single features via mean, variance, distribution curves), bivariate analysis (correlating feature pairs), multivariate analysis, outlier detection, and imbalance checks (e.g., class distribution analysis in classification).
Key points
  • Provides concrete understanding of hidden relationships between input features and target outputs.
  • Identifies class imbalances and data skews that dictate future modeling strategies.
  • Functions as the 'tool-sharpening' phase that drastically speeds up downstream modeling decisions.
When to use
Use after data cleaning to extract statistical insights and guide feature engineering.

Stage 5: Feature Engineering and Selection

What it is
Creating new informative features and filtering down existing variables to only those that positively contribute to model performance.
How it works
Feature engineering transforms or combines existing raw attributes into domain-meaningful columns (e.g., combining room and bathroom counts into square footage). Feature selection evaluates and drops redundant, non-impactful, or noisy features.
Key points
  • Reduces dimensionality to speed up training and prevent the curse of dimensionality.
  • Domain-specific features directly boost machine learning model predictive power.
  • Removes irrelevant features that do not significantly influence the output.
When to use
Use after EDA to optimize the input feature representation prior to training models.

Stage 6: Model Training, Evaluation, and Selection

What it is
The iterative experimentation phase where multiple ML algorithms are trained, hyperparameter-tuned, evaluated against performance metrics, or combined via ensembles.
How it works
Diverse algorithm families (linear models, tree ensembles, neural networks) are trained on prepared data. Performance is measured using domain metrics (Accuracy, Mean Squared Error, Dunn's Index). Models are tuned via hyperparameter tuning, and multiple models may be combined using ensemble techniques (bagging, boosting, stacking).
Key points
  • Never rely on a single algorithm; benchmark across multiple algorithmic paradigms.
  • Hyperparameter tuning optimizes settings to squeeze maximum performance out of selected algorithms.
  • Ensemble learning aggregates predictions from multiple diverse models to boost overall accuracy and robustness.
When to use
Use to discover, tune, and validate the most effective model for the target problem.

Stage 7: Model Deployment

What it is
The process of integrating the trained model into a production environment where it can receive inputs and serve live inference requests to end-users.
How it works
The model is serialized into a binary format (e.g., using Python's `pickle`), wrapped into an API endpoint, hosted on a backend server (e.g., Heroku, AWS, GCP), and integrated with user-facing clients (web or mobile apps) via JSON request/response pipelines.
Key points
  • Converts an experimental model artifact into an accessible software service.
  • Decouples model inference logic from user interface via REST APIs.
  • Requires cloud infrastructure setup (AWS, GCP, Heroku) to manage availability.
When to use
Use once a candidate model passes offline validation and is ready for integration into production software.

Stage 8: Testing (A/B Testing)

What it is
Validating the newly deployed model against real-world users under live production conditions.
How it works
The model is rolled out progressively to a subset of trusted or randomized users (beta testing / A/B testing). User interaction, accuracy, and operational feedback are compared against baselines before wider rollout.
Key points
  • Mitigates business risk by preventing sudden catastrophic failures across the full user base.
  • Identifies regressions and discrepancies between offline validation data and real user data.
  • Triggers feedback loops to revisit earlier pipeline stages if live metrics fall below expectations.
When to use
Use immediately after deployment to assess live production impact before 100% rollout.

Stage 9: Optimization & Maintenance

What it is
The continuous operations, scalability management, and retraining lifecycle required to keep the production ML system reliable and performant.
How it works
Engineers configure model/database backup and rollback mechanisms, set up server load balancers for traffic spikes, and automate retraining pipelines to counter model rotting (drift caused by evolving real-world data patterns).
Key points
  • Counteracts model rotting (performance degradation over time due to data/concept drift).
  • Requires defined retraining schedules (e.g., weekly or monthly) and automation.
  • Maintains high availability using load balancing, automated rollbacks, and disaster recovery backups.
When to use
Use continuously throughout the entire operational lifetime of a deployed production ML system.
